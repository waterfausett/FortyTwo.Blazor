# Party up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At the end of a Live game, partners can **Party up** and land on the same team in the next game, anyone can **Find a game** straight away, and **Rematch** stays, while nobody can end up in two Live games.

**Architecture:** Choices live on the finished match (`MatchState`), enforced by pure functions in `@fortytwo/rules` (`party.ts`) and applied by `MatchDO`. The second Party up press calls a new `Matchmaker.playPair`, which seats both partners in one MatchDO update and is also the "already in a Live game" authority (`liveBusy`) for Party up and Rematch. A per-player 30 s lapse, kept in MatchDO storage and run from its alarm, withdraws the choices of players who left the screen. Web and mobile render one shared view model (`endChoices` in `@fortytwo/client`).

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects (vitest-pool-workers), React (web, vitest), React Native/Expo (mobile, jest).

**Spec:** `docs/superpowers/specs/2026-10-18-party-up-design.md`

## Global Constraints

- Live only. Every other mode's end screen and rematch behave exactly as today, and Daily rematch votes never lapse.
- New `MatchState` fields are optional; stored matches must still read.
- Button copy: **Party up with <name>**, **Find a game**, **Rematch**; states: "<name> wants to party up ✓", "Waiting for <name>…", "<name> left", "<name> is in another game", **Go to your new game**.
- Game-screen panel: buttons stacked Party up (team colour `us` turquoise), Find a game (brass), Rematch (outline). Summary sheet: row **Lobby | Rematch**, row **Find a game | Party up**.
- Grace period `PARTY_GRACE_MS = 30_000`.
- Live solo seat order 0, 2, 1, 3; Daily keeps 0, 1, 2, 3.
- Comments in this repo explain *why* in plain sentences above the code; match that density.
- Worker tests: `npm test -w @fortytwo/worker` (if vitest-pool-workers fails on Node 26, use Node 25 via nvm). Rules: `npm test -w @fortytwo/rules`. Client: `npm test -w @fortytwo/client`. Web: `npm test -w @fortytwo/web`. Mobile: `npm test -w @fortytwo/mobile`, `npm run lint -w @fortytwo/mobile`, `npx tsc --noEmit` in `apps/mobile`. Check each package's `name` in its package.json if a `-w` name doesn't resolve.

## Review Focus

1. **Both partners press Party up at the same moment.** Each request sees the other's offer and calls `playPair`. Expect one table, both seated once (Task 5 idempotency test).
2. **A Live rematch retried after its match was created.** Its voters are indexed at the rematch table and must not count as "busy" (Task 6, `except` test).
3. **A partner who was backgrounded when the last trick fell.** No socket close ever fires for them; the lapse must still start at the win (Task 7 test).
4. **Coming back within 30 s, or after.** Within: nothing changes. After: `away` clears and buttons revive, but the offer is gone (Task 7 tests).
5. **Pair claim at a game under way, alongside an earlier solo claim.** The solo claimant must not take the pair's pinned seat at the break (Task 2 test).

**Interfaces:**
- Produces, on `MatchState` (all optional, documented like the neighbours):
  - `partyOffers?: string[]`
  - `movedOn?: Record<string, 'left' | 'busy'>` (pressed Find a game / found in another Live game: final)
  - `away?: string[]` (lapsed, cleared when they come back)
  - `partyMatchIds?: Partial<Record<Teams, string>>`
- Produces, from `party.ts`:
  - `PARTY_GRACE_MS = 30_000`
  - `partnerOf(match: MatchState, playerId: string): string | null`: the other seat on their team, or null if empty.
  - `offerParty(match, playerId): MatchState`: asserts Live (`matchMode`), won, `assertIsMatchPlayer`, partner is a person (`!isBot`), team not in `partyMatchIds`, partner not in `movedOn`/`away`, self not in `movedOn`. Adds the offer (idempotent), removes the player's rematch vote.

  - `partyAgreed(match, playerId): boolean`: both partners in `partyOffers`.
  - `moveOn(match, playerId, why: 'left' | 'busy'): MatchState`: removes offer and rematch vote, sets `movedOn[playerId]` (first reason kept).
  - `setAway(match, playerId, away: boolean): MatchState`: true removes offer + vote and adds to `away`; false removes from `away`. Returns `match` unchanged (same object) when nothing changes, so callers can skip a save.
  - `recordParty(match, team: Teams, matchId: string): MatchState`: sets `partyMatchIds[team]`, clears both partners' offers.
  - `rematchBlocked(match): boolean`: Live and (a human in `movedOn` or `away`, or any `partyMatchIds` entry).
- `voteRematch` (matchEngine.ts): in Live, throws `ValidationError('No rematch', ...)` when `rematchBlocked`; removes the voter's party offer.

### Task 7: Offers lapse 30 s after leaving the screen

**Files:**
- Modify: `apps/worker/src/matchDO.ts`
- Test: create `apps/worker/test/matchDOPartyLapse.test.ts` (copy the JWKS/`signToken`/`openSocket` helpers from `matchDOSocket.test.ts`)

**Interfaces:**
- Storage key `'lapses'`: `Record<string, number>` (playerId → epoch ms due).
- Only for a Live match that is won, and only for human seated players:
  - **On a player's last socket closing** (`webSocketClose`, counting their sockets other than the closing one): `lapses[player] = Date.now() + PARTY_GRACE_MS`, then `scheduleLapse()`.
  - **On the winning save** (in `update()` and `alarm()`, next to `recordStatsIfWon`): a lapse for each human not in `watchingPlayers()` and not in `onTheWay` (Review Focus 3).
  - **On upgrade** (`handleWebSocketUpgrade`): delete `lapses[player]`. If they're in `away`, `setAway(false)`, save, broadcast.
  - **`alarm()`**: before the ML bot is resolved, read `'lapses'`. If any are due: load the match, `setAway(true)` for each due player, remove them from `lapses`, save, publish, `scheduleLapse()`, return. Otherwise continue as today.
  - `private async scheduleLapse()`: sets the alarm to the earliest pending lapse, unless an earlier alarm is already set.

  ```ts
  export type PartyButton =
    | { kind: 'hidden' }                          // not Live, not won, viewer not seated, bot partner, or viewer moved on
    | { kind: 'offer'; partnerOffered: boolean }  // "Party up with Sam" (+ "Sam wants to party up ✓")
    | { kind: 'waiting' }                         // my offer stands; tap cancels
    | { kind: 'partnerLeft' }                     // partner movedOn 'left' or away

    live: boolean;           // show the Live panel at all
    partnerId: string | null;
    party: PartyButton;
    rematchDisabled: boolean; // rematchBlocked, or my offer stands
    iAmBusy: boolean;         // movedOn[me] === 'busy': the client sends me back to my Live game
  }
  export function endChoices(match: MatchState, myPlayerId: string): EndChoices
  ```
  Precedence for `party`: `partied` > `hidden` > `partnerBusy` > `partnerLeft` > `waiting` > `offer`.
